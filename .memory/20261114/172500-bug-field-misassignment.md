# bug：金额字段取错 + 合同把"付款方式"当"付款方"

- 时间：2026-11-14 17:25 (+08:00)
- 类型：bug
- 影响范围：`backend/app/pipeline/extract.py`
- 关联提交：R1.0 初始实现内修复

## 现象（首轮 14 份合成单据实测）

| 单据 | 错误 |
|---|---|
| 增值税专用发票 | `amount_total` 取成 8,500.00（不含税合计），应为价税合计 9,605.00 |
| 采购订单 | `seller` 取成"承担"（来自"运费由供应商承担"） |
| 合同 | `buyer` 取成"式: 合同签署后 10 个工作日内支付 50%…"（来自"三、付款方式："） |
| 增值税发票 | `amount_net` 缺失（发票上的"合计金额"被 `amount_total` 抢走） |

## 根因（四个独立问题）

1. **同规则内别名没有优先级**：`合计金额` 与 `价税合计` 都在 `amount_total` 别名表里，
   谁先被扫描到谁生效，导致不含税额覆盖了含税额。
2. **标签没有边界判断**：`付款方` 命中 `付款方式`，`供应商` 命中 `运费由供应商承担`。
3. **候选值未做类型校验**：`税率` 右侧恰好是另一个标签 `税额`，被当成税率值。
4. **金额口径没有按单据类型区分**：发票的"合计金额"是不含税口径，其他单据的"合计金额"是总价。

## 修复

| 问题 | 方案 |
|---|---|
| 1 | `chosen[key] = (别名优先级, 行置信度, 值)`，别名在规则里的声明顺序即权威度 |
| 2 | `_label_at()`：别名前一个字符不能是汉字、后一个字符不能是汉字 |
| 3 | `_plausible(kind, text)`：金额要有数字、日期要能解析、账号要够位数、币种走白名单，逐个候选试 |
| 4 | `Rule.only_types`：新增"仅增值税发票"的 `amount_net` 规则，构建别名索引时类型限定优先 |

## 回归验证

同一批 14 份合成单据重跑：

- 增值税专用发票：`amount_total=9,605.00`、`amount_net=8,500.00`、`amount_tax=1,105.00`，勾稽通过；
- 采购订单：`seller=苏州恒信电子有限公司`；
- 合同：`buyer=杭州云枢科技有限公司`、`amount_total=128,000.00`，整单自动通过；
- 收据：`amount_total=35,000.00`（"金额（小写）"命中）。

## 教训

标签型抽取的失败模式不是"抽不到"，而是"抽到隔壁"。
必须同时具备：别名优先级、词边界、值形态校验，三者缺一都会产生"看起来合理"的错值。
