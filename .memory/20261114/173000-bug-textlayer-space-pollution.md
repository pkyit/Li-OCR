# bug：PDF 文本层重建时中文被插入空格

- 时间：2026-11-14 17:30 (+08:00)
- 类型：bug
- 影响范围：`backend/app/pipeline/io.py:_lines_from_pdf_text`
- 关联提交：R1.0 初始实现内修复

## 现象

文本层 PDF（确定性抽取路径）抽出的值带杂空格：

- `invoice_code = "031 0021 0021 1"`
- `doc_date = "2026年1 1月06日"`
- `tax_id = "91 330203MA2AF9K7QM"`

归一化后业务值正确，但复核页显示脏值，训练裁剪图的标签也会被污染。

## 根因

按字符坐标重建行时，用"相邻字符间距 > 0.45 × 平均字宽"就补一个空格。
中文按字排布、字宽不齐（尤其数字与标点混排），这个阈值过低，导致正常字距被判为空格。

## 修复

只在**间距 > 0.95 × 平均字宽**且**两侧都是 ASCII 字符**时补空格。
中文之间不再插空格；真正的空格字符本来就在 PDF 字符流里，会被原样保留。

## 回归验证

同一份文本层发票重抽：`031002100211` / `2026年11月06日` / `91330203MA2AF9K7QM`，无杂空格。

## 教训

同一份数据有两条抽取路径（文本层 / OCR），显示口径必须一致；
凡是"启发式补字符"，都要用真实样本回放验证，不能靠直觉阈值。
