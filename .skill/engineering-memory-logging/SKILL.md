# 记忆与技能沉淀套路

## 何时写 .memory

只要发生了下面任一事件，就必须落一个文件，不攒着：

- 做了技术选型或推翻了之前的选型；
- 修了一个"不修就会再次踩"的 bug；
- 发现了新风险/漏洞/未验证项（`NEEDS CHECK`）；
- 跑出了用于对外汇报的实测数字。

## 命名与结构

```
.memory/<YYYYMMDD>/<HHMMSS>-<type>-<slug>.md
type ∈ decision | bug | risk | verify
```

正文四段：`背景` / `结论` / `证据` / `后续`。
`证据` 必须有可复现命令或具体数字，禁止"测试通过"这类空话。

## 写作纪律

1. **只写后来者不知道就会踩的信息**：现象、根因、否决了什么、怎么验证。
2. **不抄代码**：贴文件路径 + 函数名即可，代码会变，记录会过期。
3. **不写凭据**：口令、token、kubeconfig 一律只写"从环境变量读取"。
4. **判断句要能落地**："交叉验证不产生真值"要跟一句"因此冲突必须人工复核"。

## 何时写 .skill

同一套操作第二次被需要时，就写成技能，而不是再解释一遍。
判定标准：有明确输入、有固定步骤、有可验证的产出。

结构：

```markdown
---
name: <kebab-case>
description: <一句话：做什么 + 什么时候用 + 什么时候不要用>
---
# 标题
## 何时用 / 不适用
## 步骤（可复制的命令）
## 检查点（怎么知道成功了）
## 坑
```

## 反例

- 把整个对话总结贴进 memory：没有价值，检索还慢。
- 技能里写"根据实际情况调整"：等于没写。
- 一次改动写五个文件：一个决策一个文件。
