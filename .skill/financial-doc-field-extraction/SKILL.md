# 金融单据字段抽取套路

## 何时用

需要从 OCR 文本行（带 bbox）里稳定抽出金额、日期、税号、账号、往来单位等字段时。
不适用于：需要理解表格行列语义的场景（那要做列归属，见 R1.1）。

## 四层防线（缺一层就会出错值）

1. **别名优先级**
   同一字段的多个别名按"越具体越靠前"排序，命中后按 `(别名优先级, 行置信度)` 择优。
   典型：`价税合计` > `合计金额` > `合计`。
2. **词边界**
   `付款方` 不能命中 `付款方式`，`供应商` 不能命中 `运费由供应商承担`。
   规则：别名前一个字符不能是汉字、后一个字符不能是汉字（数字/标点可以）。
3. **值形态可信性**
   金额必须含数字、日期必须能被解析、账号位数 ≥8、税率含 `%`、币种走白名单。
   取值时把"同行右侧 → 下方邻近"的候选依次喂给校验，第一个可信的才采纳。
4. **单据类型限定**
   同名标签在不同单据口径不同：发票的"合计金额"是不含税额，采购单的"合计金额"是总价。
   用 `only_types` 为特定类型注册专用规则，构建别名索引时类型限定规则优先。

## 标准实现顺序

```
cleaned = 全角转半角 + 去前导分隔符
hit = 按"长别名优先"扫描 cleaned，找到第一个通过词边界的别名
for 候选 in [同行右侧残文, 同行右侧块, 下方邻近块]:
    if 形态符合(kind, 候选): 取值并 break
归一化：金额 Decimal 两位、日期 ISO、账号去空格、税号大写
```

## 必备校验（比模型置信度可靠）

| 校验 | 实现 |
|---|---|
| 金额勾稽 | `不含税 + 税额 == 价税合计`，容差 0.02 |
| 统一社会信用代码 | GB32100-2015 加权和校验位 |
| 金额小数位 | 原值必须两位小数，否则标 `FORMAT` |
| 日期合理性 | 1990 ~ 今天+10 年 |

## 无标签字段（手写 / 无表头）

有标签才走几何；没有标签时只认"能自证"的强模式：

1. 卡号：全页扫 `(?<!\d)\d[\d\s\-/]{12,24}\d(?!\d)`，先做 OCR 混淆修复（`/`→`1`、`O`→`0`），
   **必须 Luhn 通过**才采纳；多个候选按"修复过 > 未修复、位数多 > 位数少"择优。
2. 税号：扫 18 位 `[0-9A-Z]`，**必须过 GB32100 校验位**。
3. 结果一律标 `INFERRED`（来自 VL 再加 `VL_FALLBACK`），单据强制人工复核，不进自动通过。
4. 宁可 MISSING，也不要用"日期串/流水号"凑一个像卡号的值。

手写/低质量页的处理顺序：质量门（字符量<40 或 均置信度<0.80 或 低置信占比>0.35）
→ VL 补文本证据 → 只做行内取值（VL 无坐标，禁止几何邻近）→ 强制复核。

## 调优流程（用工具，不要靠猜）

```powershell
python -m tools.ingest_local samples --sync     # 重跑
python -m tools.inspect_doc --all               # 看每单字段与 flags
```

- 出现"抽到隔壁标签"：先看是不是值形态不合格，再加/改 `_plausible`。
- 出现"两个字段抢同一行"：看别名优先级，必要时新增 `only_types` 规则。
- 批量出现同一错误：先怀疑模板/别名，不要先去调模型。

## 坑

- OCR 会把多个标签合并成一行：一行只能喂一个规则，合并行天然丢字段，需要按 x 坐标切分（R1.1）。
- 文本层 PDF 与 OCR 两条路径都要校验，否则显示口径不一致。
- 置信度是模型自评分，不校准就不能当概率用。
- 后台线程里创建 PaddleOCR-VL 前先 `paddle.disable_static()` + `paddle.set_device()`，
  否则 `paddle.amp.is_bfloat16_supported()` 会拿到 `Place(undefined:0)` 直接报错。
- VL 常驻约 7.9GB，用完必须卸载并 `empty_cache()`，否则 8GB 卡上主引擎随时可能 OOM。
